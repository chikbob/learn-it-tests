# Безопасность LearnIT Tests

## Что уже защищено в коде

- Vercel обслуживает статическое приложение через HTTPS и автоматически фильтрует DDoS-трафик.
- CSP запрещает сторонние скрипты, фреймы, плагины и неизвестные сетевые подключения.
- HSTS, `nosniff`, `DENY` для iframe и ограниченная `Permissions-Policy` заданы в `vercel.json`.
- Supabase RLS изолирует прогресс пользователей; административная RPC повторно проверяет роль в базе.
- RPC рейтинга идемпотентна, сериализует параллельные записи и принимает не более 100 симуляций от аккаунта за 24 часа.
- JSON прогресса ограничен 512 КиБ и проверяется по базовой структуре.
- Сетевые запросы клиента прерываются через 20 секунд, а поврежденный локальный кэш безопасно сбрасывается.
- Секретный ключ Supabase не используется в браузере; publishable key является публичным по назначению.

## Настройки хостинга

Эти меры нельзя надежно заменить кодом Vue и их следует контролировать в панелях сервисов.

### Vercel

1. Откройте проект → **Firewall** и контролируйте вкладки **Traffic** и **Events**.
2. При атаке временно включите **Attack Challenge Mode**.
3. Добавьте WAF rate-limit или challenge для частых запросов к `/supabase/auth/v1/signup`, `/supabase/auth/v1/token` и `/supabase/auth/v1/recover`.
4. Ограничьте доступ к preview deployments и удаляйте старые переменные/домены.

### Supabase

1. В **Authentication → Rate Limits** не увеличивайте лимиты без необходимости.
2. В **Authentication → Bot and Abuse Protection** подключите Cloudflare Turnstile или hCaptcha перед публичным запуском. После включения CAPTCHA клиент должен передавать выданный токен в `signUp` и `signInWithPassword`.
3. Включите MFA для владельцев организации Supabase и GitHub.
4. Регулярно проверяйте **Auth Logs**, **Postgres Logs** и рост таблицы `simulation_attempts`.
5. Используйте собственный SMTP: встроенный отправитель ограничен и предназначен только для тестирования.

## Реагирование

При аномальном трафике сначала включите Vercel Attack Challenge, затем изучите Firewall Events и Supabase Logs. Не публикуйте access token, пароль базы или service-role key. При утечке немедленно отзовите токен, смените пароль базы и завершите активные пользовательские сессии при необходимости.
